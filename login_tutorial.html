一、專案概覽

TestApp 是一個以 ASP.NET Core Minimal API 風格撰寫的輕量後端專案，目標框架為 .NET 10.0。整個應用程式僅包含一個主要程式檔 Program.cs，無需 Controller 或 Startup 類別，適合快速原型開發或學習用途。

1.1 現有 API 端點

端點HTTP 方法說明
/helloGET回傳固定字串 "hello matt"
/weatherforecastGET回傳五筆隨機天氣資料（範例用）
/loginPOST本文件重點：驗證帳號密碼並回傳結果

1.2 已知問題

  • 密碼明文儲存於 users.csv，未使用 Hash（如 bcrypt）
  • 登入成功後未發放 JWT Token，後端無法識別後續請求身份
  • 每次登入都重新讀取 CSV 檔，無快取機制
  • app.UseHttpsRedirection() 被注解掉，未強制 HTTPS
  • TodoItem record 已定義但無對應 API

二、POST /login 完整程式碼

以下是 Program.cs 中登入 API 的完整程式碼，供後續逐行解說參考：

app.MapPost("/login", (LoginRequest req) =>
{
    var csvPath = Path.Combine(Directory.GetCurrentDirectory(), "users.csv");
    if (!File.Exists(csvPath))
        return Results.Problem("找不到使用者資料檔");

    var users = File.ReadAllLines(csvPath)
        .Skip(1)
        .Select(line => line.Split(','))
        .Where(parts => parts.Length == 2)
        .Select(parts => (Username: parts[0].Trim(), Password: parts[1].Trim()))
        .ToList();

    var matched = users.FirstOrDefault(u =>
        u.Username == req.Username && u.Password == req.Password);

    if (matched == default)
        return Results.Json(new { success = false, message = "帳號或密碼錯誤" },
            statusCode: 401);

    return Results.Json(new { success = true, username = matched.Username });
});

三、逐行詳細解說

3.1 宣告 POST 端點並接收請求

app.MapPost("/login", (LoginRequest req) =>

MapPost 方法向 ASP.NET Core 的路由系統登記一個 POST 端點，路徑為 /login。

括號內的參數 LoginRequest req 是「模型繫結（Model Binding）」的體現——ASP.NET 會自動把 HTTP Request Body 的 JSON 反序列化成 LoginRequest 物件。

LoginRequest 定義在檔案最底部：

record LoginRequest(string Username, string Password);

用戶端呼叫時必須傳入符合此結構的 JSON，例如：

{ "username": "admin", "password": "admin123" }

3.2 組出 CSV 檔案的完整路徑

var csvPath = Path.Combine(Directory.GetCurrentDirectory(), "users.csv");

Directory.GetCurrentDirectory() 取得程式的工作目錄（通常是專案根目錄）。Path.Combine 以安全方式把目錄與檔名拼接，自動處理斜線問題，避免手動字串拼接時在不同作業系統產生錯誤路徑。

3.3 檔案存在性檢查

if (!File.Exists(csvPath))
    return Results.Problem("找不到使用者資料檔");

若 users.csv 不存在，提早回傳以避免後續程式拋出例外。Results.Problem 回傳 HTTP 500，回應 body 為標準的 RFC 7807 ProblemDetails JSON 格式，方便前端統一解析錯誤。

3.4 讀取 CSV 並轉換為 List（LINQ 鏈式操作）

以下五行是一條 LINQ 鏈式查詢，逐步把 CSV 的原始文字轉換成結構化的使用者清單：

程式碼說明
File.ReadAllLines(csvPath) 把整個 CSV 讀入，每行變成一個字串，回傳 string[]
.Skip(1) 跳過第一行標題列（username,password），從第二行開始
.Select(line => line.Split(',')) 每行以逗號切割，"admin,admin123" 變成 ["admin", "admin123"]
.Where(parts => parts.Length == 2) 過濾掉欄位數不等於 2 的行（空白行、格式錯誤行），防止陣列越界
.Select(parts => (Username: parts[0].Trim(), Password: parts[1].Trim())) 轉成具名 tuple，.Trim() 去除前後空白，防止比對失敗
.ToList() 執行整條 LINQ 查詢，結果存入 List

3.5 .ToList() 後的資料樣貌

以 users.csv 的實際內容為例：

username,password
admin,admin123
user1,password1

執行完 .ToList() 之後，變數 users 的內容為：

IndexUsernamePassword
0"admin""admin123"
1"user1""password1"

標題列（username,password）已被 .Skip(1) 排除，不會出現在清單中。

3.6 比對帳號密碼

var matched = users.FirstOrDefault(u =>
    u.Username == req.Username && u.Password == req.Password);

FirstOrDefault 在清單中找第一個同時符合帳號與密碼的元素。若找到，回傳該 tuple；若找不到，回傳 tuple 的預設值（即 default，兩個欄位皆為 null）。

3.7 登入失敗回應

if (matched == default)
    return Results.Json(new { success = false, message = "帳號或密碼錯誤" },
        statusCode: 401);

當 matched 等於 default（表示查無使用者），回傳 HTTP 401 Unauthorized，body 為：

{ "success": false, "message": "帳號或密碼錯誤" }

注意：無論是帳號不存在還是密碼錯誤，都統一回傳相同的錯誤訊息，這是安全設計原則——不讓攻擊者得知帳號是否存在。

3.8 登入成功回應

return Results.Json(new { success = true, username = matched.Username });

登入成功，回傳 HTTP 200 OK，body 為：

{ "success": true, "username": "admin" }

4.2 HTML 結構部分逐行解說

程式碼說明
<!DOCTYPE html> 文件類型宣告，告訴瀏覽器這是 HTML5，確保它用標準模式解析，而非舊版相容模式
<html lang="zh-TW"> HTML 根元素。lang="zh-TW" 指定語言為繁體中文，有助於螢幕閱讀器和搜尋引擎理解頁面語言
<meta charset="UTF-8" /> 指定字元編碼為 UTF-8，確保中文字不會顯示成亂碼
<title>登入</title> 瀏覽器分頁上顯示的標題文字，不會出現在頁面內容中
<h1>登入</h1> 頁面最大標題。<h1> 是語意標籤，代表頁面主標題，一個頁面通常只放一個
<label>帳號：<input id="username" type="text" /></label> <label> 把文字與輸入框綁在一起，點擊「帳號：」文字也能讓輸入框取得焦點。id="username" 給輸入框命名，供 JavaScript 取值用。type="text" 為一般文字輸入
<input id="password" type="password" /> type="password" 讓輸入的字元自動變成 ● 遮蔽，防止旁人看到密碼
<button onclick="login()">登入</button> 按鈕元素。onclick="login()" 表示點擊時執行 JavaScript 的 login() 函式
<p id="message"></p> 空段落，預設不顯示任何文字。登入結果（成功或錯誤訊息）由 JavaScript 填入這裡

4.3 JavaScript 部分逐行解說

宣告非同步函式

async function login() { ... }

async 把 login 宣告為非同步函式，讓函式內部可以使用 await。當 await 在等待網路回應時，瀏覽器不會卡住，使用者仍可操作頁面其他部分。

讀取輸入框的值

const username = document.getElementById('username').value;
const password = document.getElementById('password').value;

document.getElementById('username') 找到頁面上 id 為 username 的元素（帳號輸入框），.value 取出使用者輸入的文字。密碼同理。

發送 API 請求（fetch）

const res = await fetch('/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ username, password })
});

fetch 是瀏覽器內建的 HTTP 請求 API，各參數說明如下：

參數值說明
URL '/login' 相對路徑，指目前網站的 /login，也就是後端的 POST /login 端點。不需寫 http://localhost:5000，瀏覽器會自動補上
method 'POST' HTTP 方法設為 POST，對應後端的 app.MapPost
headers Content-Type: application/json 告訴後端「我送的 body 是 JSON 格式」，後端才知道要用 JSON 反序列化
body JSON.stringify({username, password}) JSON.stringify 把 JavaScript 物件轉成 JSON 字串。{username, password} 是 ES6 縮寫，等同於 {username: username, password: password}

await 讓程式暫停在此，等後端回應後才繼續往下執行，回應結果存入 res。

解析回應 JSON

const data = await res.json();

res 是後端的 HTTP 回應物件，.json() 把回應 body 的 JSON 字串解析成 JavaScript 物件。此時 data 的內容會是以下其中一種：

情況data 的值
登入成功{ success: true, username: "admin" }
登入失敗{ success: false, message: "帳號或密碼錯誤" }

顯示結果訊息

document.getElementById('message').textContent =
  data.success ? `歡迎，${data.username}！` : data.message;

找到 id="message" 的空段落，把文字填入。使用三元運算子：

  • data.success 為 true：顯示 歡迎，admin！（反引號的樣板字串，${data.username} 自動插入使用者名稱）
  • data.success 為 false：顯示後端回傳的 data.message（即「帳號或密碼錯誤」）

textContent 而非 innerHTML：只插入純文字，防止 XSS 攻擊（若用 innerHTML，惡意使用者可注入 HTML/JavaScript）。

七、xUnit 單元測試

手動測試只能驗證「現在」的行為，每次改程式後都要重新手動測。自動化測試讓你執行一個指令就能確認所有情境仍然正確，是專業開發的基本功。

xUnit 是 .NET 生態系最主流的測試框架，ASP.NET Core 官方範本預設也使用它。

7.1 建立測試專案

# 在 TestApp 的上一層目錄執行

cd TestApp.Tests
dotnet add reference ../TestApp/TestApp.csproj

執行後目錄結構會變成：

TestApp/          ← 主專案

7.2 單元測試的概念

單元測試的目標是測試「一個小的獨立邏輯單元」，隔離外部依賴（資料庫、檔案系統、網路）。

目前 /login 的驗證邏輯混在端點裡，比較難單獨測試。常見的做法是把邏輯抽成獨立函式，再對函式寫測試。以下示範如何重構並測試。

7.3 抽出可測試的驗證邏輯

在 TestApp 專案中新增 AuthService.cs：

// AuthService.cs
public static class AuthService
{
    /// <summary>
    /// 從 CSV 行清單中比對帳密，回傳使用者名稱；找不到則回傳 null。
    /// </summary>
    public static string? Authenticate(
        IEnumerable<string> csvLines,
        string username,
        string password)
    {
        var matched = csvLines
            .Skip(1)
            .Select(line => line.Split(','))
            .Where(parts => parts.Length == 2)
            .Select(parts => (Username: parts[0].Trim(), Password: parts[1].Trim()))
            .FirstOrDefault(u => u.Username == username && u.Password == password);

        return matched == default ? null : matched.Username;
    }
}

7.4 撰寫 xUnit 測試

在 TestApp.Tests 新增 AuthServiceTests.cs：

// AuthServiceTests.cs
public class AuthServiceTests
{
    // 測試用的假 CSV 資料（不依賴真實檔案）
    private readonly string[] _csvLines =
    [
        "username,password",
        "admin,admin123",
        "user1,password1"
    ];

    // [Fact] 表示這是一個測試案例

    [Fact]
    public void Authenticate_正確帳密_回傳使用者名稱()
    {
        // Arrange（準備）
        var username = "admin";
        var password = "admin123";

        // Act（執行）
        var result = AuthService.Authenticate(_csvLines, username, password);

        // Assert（驗證）
        Assert.Equal("admin", result);
    }

    [Fact]
    public void Authenticate_錯誤密碼_回傳null()
    {
        var result = AuthService.Authenticate(_csvLines, "admin", "wrongpass");
        Assert.Null(result);
    }

    [Fact]
    public void Authenticate_不存在帳號_回傳null()
    {
        var result = AuthService.Authenticate(_csvLines, "nobody", "password1");
        Assert.Null(result);
    }

    [Fact]
    public void Authenticate_空白帳號_回傳null()
    {
        var result = AuthService.Authenticate(_csvLines, "", "");
        Assert.Null(result);
    }

    [Fact]
    public void Authenticate_CSV有多餘空格_仍可比對成功()
    {
        // 測試 .Trim() 是否有效
        var csvWithSpaces = new[] { "username,password", " admin , admin123 " };
        var result = AuthService.Authenticate(csvWithSpaces, "admin", "admin123");
        Assert.Equal("admin", result);
    }
}

7.6 xUnit 三大核心概念

概念說明範例
[Fact] 單一固定測試案例，不帶參數 測試「正確帳密回傳使用者名稱」
[Theory] + [InlineData] 同一邏輯，帶入多組不同資料測試 一次測試多組錯誤帳密組合
Arrange / Act / Assert 測試的三段式結構：準備資料 → 執行邏輯 → 驗證結果 每個 [Fact] 方法的內部結構

7.7 [Theory] 範例：一次測試多組資料

[Theory]
[InlineData("admin",  "wrongpass")]
[InlineData("nobody", "password1")]
[InlineData("",       "")]
public void Authenticate_無效輸入_皆回傳null(string username, string password)
{
    var result = AuthService.Authenticate(_csvLines, username, password);
    Assert.Null(result);
}

這段程式會自動執行三次，分別帶入三組 [InlineData] 的資料，等同三個獨立 [Fact]，但程式碼更簡潔。

      // 前端驗證（不需要發送請求就能攔截明顯錯誤）
      if (!username || !password) { showMessage('帳號與密碼不可為空', false); return; }
      if (password !== confirmPassword) { showMessage('兩次輸入的密碼不一致', false); return; }

      const res = await fetch('/register', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ username, password })
      });

      const data = await res.json();
      showMessage(data.message, data.success);

      // 成功後 2 秒自動跳回登入頁
      if (data.success) setTimeout(() => { window.location.href = '/'; }, 2000);
    }

    function showMessage(text, isSuccess) {
      const el = document.getElementById('message');
      el.textContent = text;
      el.className   = isSuccess ? 'success' : 'error';
    }
  </script>
</body>
</html>

8.2 register.html 重點解說

程式碼說明
type="password"（兩個欄位） 密碼與確認密碼都用 type="password" 遮蔽顯示，防止旁人看到
.value.trim() 帳號欄位去除前後空白，防止使用者不小心輸入空格造成的奇怪帳號。密碼欄位不 trim，保留使用者刻意輸入的空白
password !== confirmPassword 前端在送出前先比對兩次輸入，不一致就直接顯示錯誤，不消耗後端資源
fetch('/register', { method: 'POST', ... }) 呼叫後端的 POST /register 端點，與 /login 的呼叫方式完全相同
setTimeout(..., 2000) 成功建立帳號後，讓使用者看到成功訊息 2 秒，再自動導向登入頁，提升體驗
el.className = isSuccess ? 'success' : 'error' 用 CSS class 切換訊息顏色（綠色成功 / 紅色失敗），而非用 style 直接操作，更好維護

8.3 AuthService.UserExists() 解說

public static bool UserExists(IEnumerable<string> csvLines, string username)
{
    return csvLines
        .Skip(1)
        .Select(line => line.Split(','))
        .Where(parts => parts.Length == 2)
        .Any(parts => parts[0].Trim()
            .Equals(username, StringComparison.OrdinalIgnoreCase));
}
程式碼說明
.Any(...) 只要找到一筆就回傳 true，比 FirstOrDefault 更語意清晰（我們只想知道「存不存在」）
StringComparison.OrdinalIgnoreCase 大小寫不分的比對。避免使用者用 ADMIN 搶占已有的 admin 帳號

8.4 POST /register 端點完整程式碼

app.MapPost("/register", (RegisterRequest req) =>
{
    // ① 基本驗證：欄位不可為空
    if (string.IsNullOrWhiteSpace(req.Username) || string.IsNullOrWhiteSpace(req.Password))
        return Results.Json(new { success = false, message = "帳號與密碼不可為空" },
            statusCode: 400);

    // ② 格式驗證：帳號不可含逗號（CSV 分隔符號）
    if (req.Username.Contains(','))
        return Results.Json(new { success = false, message = "帳號不可包含逗號" },
            statusCode: 400);

    var csvPath = Path.Combine(Directory.GetCurrentDirectory(), "users.csv");

    // ③ 若 CSV 不存在，自動建立含標題列的新檔
    if (!File.Exists(csvPath))
        File.WriteAllText(csvPath, "username,password\n");

    var csvLines = File.ReadAllLines(csvPath);

    // ④ 檢查帳號是否已存在（大小寫不分）
    if (AuthService.UserExists(csvLines, req.Username))
        return Results.Json(new { success = false, message = "此帳號已被使用" },
            statusCode: 409);

    // ⑤ 寫入新帳號到 CSV 最後一行
    File.AppendAllText(csvPath, $"{req.Username},{req.Password}\n");

    return Results.Json(
        new { success = true, message = $"帳號 {req.Username} 建立成功！" },
        statusCode: 201);
});

8.5 POST /register 逐步解說

#程式碼說明回傳狀態碼
① IsNullOrWhiteSpace 檢查帳號或密碼是否為空白（包含只有空格的情況） 400 Bad Request
② Contains(',') 帳號若含逗號會破壞 CSV 格式，必須提前攔截 400 Bad Request
③ File.WriteAllText(...) 第一次執行時 CSV 可能不存在，自動建立避免後續讀取失敗 —
④ AuthService.UserExists 帳號重複時回傳 409 Conflict（HTTP 語意：資源衝突） 409 Conflict
⑤ File.AppendAllText 用 Append 而非 WriteAll，只在最後加一行，不覆蓋現有資料 201 Created
